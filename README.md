# Totonou
 
> **メールも、タスクも、予定も。朝ひらけば、ととのう。**
>
> 一日のスタートを整える、パーソナルAI秘書。
 
Totonouは、メール・予定・タスクなど、複数の場所に散らばった情報をAIが整理し、朝ひらくだけで**「今日、自分が何をすればいいのか」**が分かるWebアプリです。
 
私たちは毎朝、本当にやりたいことを始める前に、メールや予定、Todoを見比べ、返信の要否や優先順位を判断する「一日を整理するための作業」に時間を使っています。
 
Totonouは、その整理をAI秘書に任せることで、ユーザーが本当にやるべきことにすぐ取りかかれる状態をつくります。
 
---
 
## 📌 解決したい課題
 
一日の中には、本来やりたいこと以外にも多くの「整理する作業」があります。
 
| 時間帯 | これまで必要だった作業 | Totonouが支援すること |
| --- | --- | --- |
| 🌅 朝 | メール、予定、Todoを別々に確認し、優先順位を決める | 情報を一画面に集約し、今日やることを提示 |
| ☀️ 日中 | 作業の開始・終了時刻や所要時間を記録する | Todoの操作から実績時間を自動記録 |
| 🌙 夜 | 一日の実績を思い出し、日報と改善策を書く | 実績をもとに日報を8割下書き |
 
Totonouは、**朝 → 日中 → 夜**まで、一日の流れ全体をAI秘書として支えます。

## 🔄 Totonouの一日
 
```text
🌅 朝
メール・予定・TodoをAI秘書が整理
        ↓
今日やることが決まる
 
☀️ 日中
Todoを実行
        ↓
実績時間が記録される
 
🌙 夜
AIが実績をもとに日報を下書き
        ↓
改善点を次の日へつなげる
 
🌅 翌日
また一日が、ととのう
```
 
Totonouは、単発でAIに質問するサービスではありません。**一日のスタートから終わりまでを支える、パーソナルAI秘書**を目指しています。

## ✨ 主な機能
 
### 🌅 1. 朝｜AI秘書が「今日」をまとめる
 
朝Totonouを開くと、次の情報がToday Briefingに集約されます。
 
- 今日のGoogle Calendarの予定
- メールから見つかった「要返信」「要対応」
- 自分で登録したTodo
- 今日の目標
 
AI秘書が、たとえば次のように、その日の状況を短くまとめます。
 
> 今日は予定3件、要返信2件、タスク4件。午後は少し余裕があります。
 
Todoは、単に一覧表示するのではなく、2つの軸で整理します。
 
| 軸 | 分類 |
| --- | --- |
| 優先度 | 🔴 今すぐ / 🟡 今日中 / ⚪ いつでも |
| タスクの性質 | すきまタスク / じっくりタスク |
 
目指しているのは、**「今の自分は何から始めればいいのか」まで分かる状態**です。
 
### 🧠 2. 散らばった情報を「今日やること」に変える
 
Totonouの中心にあるのは、いろいろな場所にある情報を、AI秘書が**「今日やること」へ変換すること**です。
 
```text
Gmail ─────────────┐
                   │
Google Calendar ───┼──→ Totonou ──→ 今日やること
                   │
Manual Todo ───────┘
```
 
#### ✉️ Gmail
 
メールは、AIへ渡す前にプロモーションや自動配信などを機械的に除外します。その後、AIが内容を次の4種類に分類します。
 
- 要返信
- 要対応
- 情報のみ
- 無視
 
「要返信」「要対応」のメールだけを、送信者や元メールへの導線とともにTodoへ追加します。
 
```text
メール取得
   ↓
不要メールを機械的に除外
   ↓
AIが内容を分類
   ↓
要返信 / 要対応を抽出
   ↓
今日のTodoへ
```
 
一般的なTodoアプリでは、ユーザー自身が「これをTodoにしよう」と判断して登録する必要があります。Totonouでは、**Todoにするべきこと自体をAI秘書が先に見つけます。**
 
#### 📅 Google Calendar
 
Google Calendarから当日の予定を取得し、Todoと同じToday Briefing上に表示します。
 
予定はカレンダー、やることはTodoアプリ、メールはGmailと別々に確認するのではなく、**一日の行動を一つの画面で把握できる状態**をつくります。
 
### 💬 3. AIがメール返信を下書き
 
返信が必要なメールには、AIが返信案を生成します。ただし、AIが勝手に送信することはありません。
 
```text
AIが返信案を生成
        ↓
ユーザーが確認・編集
        ↓
ユーザーが承認
        ↓
送信
```
 
メール送信のように、間違えたときの影響が大きい操作では、**AIが提案し、最後の判断は人間が行う**Human-in-the-loopを設計原則にしています。
 
### ⏱️ 4. 日中｜Todoの実行と実績記録
 
Todoを進める中で、次の実績を記録します。
 
- 何を実行したか
- いつ始めたか
- いつ終わったか
- どれくらい時間がかかったか
 
「今日は何をする予定だったか」だけではなく、**実際に何をして、どれくらい時間がかかったのか**まで残し、夜の振り返りにつなげます。
 
メール由来のTodoを完了した際には、設定に応じて元のGmailも既読化します。未完了のTodoは翌日への持ち越しを確認します。
 
### 🌙 5. 夜｜AIが日報を8割下書き
 
一日の最後には、その日の予定・Todo・実績をもとにAIが振り返りを作成します。
 
- 今日の予定と実際の結果
- 今日の目標と結果
- Good Job・感謝
- Bad Job・反省
- 改善策・明日への提案
- 自分へのエール
 
ユーザーが一日をゼロから思い出して日報を書くのではなく、**AIが8割を下書きし、人間が最後の2割を仕上げる**ことで、負担を減らしながら自分で振り返る時間を残します。

## 🤖 Devinの活用
 
この開発では、Devinを**バックエンド開発の並列実装担当**として活用しています。フロントエンドのUI開発と並行して、バックエンド側の独立しやすい作業をDevinへ切り出しました。
 
主な担当範囲は次のとおりです。
 
- Gmail連携と、検証結果を反映したメール処理フロー
- Supabaseのデータモデル・スキーマ構築
- メール、Todo、実績、日報をつなぐバックエンド処理
- デモ用シードデータの準備
- バックエンドのテストと結合時の確認
 
Devinへ曖昧な指示を一度に渡すのではなく、先にGmail MCPを実環境で検証し、検索条件、スレッド返信、既読化、Timezoneなどの挙動を確定しました。その結果を実装条件として共有することで、**AIエージェントの推測に依存せず、検証済みの仕様から実装へ進む開発フロー**を採用しています。
 
また、フロントエンドとバックエンドを分担することで、短いハッカソン期間でも複数の機能を並行して進められる体制をつくりました。

## 🗄 Supabaseの活用
 
Supabaseは、Totonouの**データ永続化基盤**として採用しています。メールから抽出した情報、Todo、作業実績、日報、設定を一つのデータ基盤でつなぐことで、朝・日中・夜の体験を連続させます。
 
| データ | 用途 |
| --- | --- |
| `messages` | 取得したメール、アカウント、分類結果、受信日時を保存 |
| `tasks` | メール・手動入力・予定由来のTodoと実行状態を保存 |
| `daily_reviews` | 目標、結果、Good Job、反省、改善策、エールを保存 |
| `activity_logs` | AIや連携処理の実行履歴を構造化して保存 |
| `settings` | メール取得範囲、既読化、AI秘書の設定などを保存 |
 
実装・設計上の工夫は次のとおりです。
 
- すべての主要データに`user_id`を持たせ、将来のマルチユーザー化に備える
- 日時はUTCで保存し、画面表示時にJSTへ変換する
- AIの処理履歴を`activity_logs`へ記録し、処理状況の表示や日報生成に再利用する
- メール本文、氏名、メールアドレス、APIキーなどの個人情報・秘密情報をログへ残さない
- APIキーとOAuthトークンは環境変数で管理し、リポジトリへコミットしない
 
現在のコア開発は単一ユーザー構成を優先しつつ、次のフェーズではSupabase AuthによるGoogleログインと、Row Level Security（RLS）によるユーザー単位のアクセス制御を想定しています。

## 🔬 Gmail MCPを計40回、実環境で検証
 
Gmail連携は、実装前にGmail MCPを**計40回**実行し、実データで挙動を確認しました。
 
検証対象には、次の内容が含まれます。
 
- Gmail検索と取得範囲
- CategoryとLabelの挙動
- HTMLメールの前処理
- 既読・未読の変更
- スレッド返信
- UTC・JST・Gmailアカウント側Timezoneの差
- 一覧取得とメール詳細取得の使い分け
 
### `category:personal`を私信と決めつけない
 
実測では、`category:personal`は単純な「私信」ではなく、ほかのCategoryへ分類されなかったメールも含む残余的なグループでした。一方で、私信やコミュニティメールは`category:forums`に多く存在していました。
 
この結果から、`category:forums`を優先候補として取得し、`category:promotions`と`category:social`を検索段階で除外する設計にしています。
 
### スレッドを維持した返信
 
返信時は、Gmailの`threadId`を指定することで元のスレッドへ接続できることを確認しました。取得できないRFC 822のMessage-IDに依存する`inReplyTo`は使わず、検証で動作した方法を採用しています。
 
### Todo完了とGmailの既読状態を連動
 
`modify_email`を使い、`UNREAD`の付与・削除が双方向に動作することを確認しました。これにより、Totonou上でメール由来のTodoを完了した際に、設定に応じて元のメールも既読化できます。
 
### TimezoneをUTCへ正規化
 
検証では、UTC、JST、Gmailアカウント側Timezoneが混在する問題を確認しました。そのため、取得時に日時をUTCへ正規化し、表示時にJSTへ変換します。期間検索では境界を重ねて取得し、`messageId`で重複を除外する方針です。
 
### AIへ渡す前の前処理
 
HTMLメールはタグやコメントを除去し、不要なトークン消費を抑えます。また、一覧取得後に必要なメールだけ詳細取得し、取得済みメールは`messageId`単位で再利用します。
 
単にAPIやMCPを接続するのではなく、**実際に動かして分かった挙動を、サービス設計と実装条件へ反映したこと**がTotonouの大きな特徴です。

## 💡 設計で大切にしていること
 
### 🙋 「人間はサボる」ことまで考える
 
Todoアプリは、毎日完璧に使い続けられるとは限りません。一日開かなかったことでTodoが溜まり、見ること自体が嫌になってしまうこともあります。
 
Totonouでは、未完了のTodoに対してAI秘書が次の選択肢を提案し、ユーザーが戻ってこられる仕組みを目指しています。
 
- 明日に回す
- 小さく分ける
- やめる
 
目指すのは、**サボらない人のためのAI秘書ではなく、サボった次の日でも戻ってこられるAI秘書**です。
 
### 🤝 効率化だけでなく、人の温かさも残す
 
Totonouは、メール・予定・Todoの整理や日報の下書きをAIに任せ、一日の負担を減らします。しかし、AI秘書の役割は効率を上げることだけではないと考えています。
 
Totonouはその日のTodoと実績を知っているからこそ、夜の日報では**「今日頑張った自分への感謝」**も下書きします。
 
将来は、日報やTodo、メールなどの個人的な情報を公開せず、本人が確認・編集した「自分への感謝」だけを共有できる仕組みを構想しています。
 
AIで一日の効率を整えながら、最後には人の言葉にも触れられる。**便利さの中に、人の温かさを残すこと**もTotonouが大切にしているポイントです。
 
### 🔐 AIにすべてを任せない
 
TotonouはAI秘書ですが、できることをすべて完全自動化することを目標にはしていません。
 
```text
AIが提案
   ↓
人間が確認・編集
   ↓
人間が承認
   ↓
実行
```
 
AIに任せる部分と、人間が判断する部分。その境界もサービス設計の一部です。

## 🛠 技術構成
 
| Technology | Usage |
| --- | --- |
| Next.js（App Router） | Webアプリとサーバー側のRoute Handler |
| Claude API | メール分類・要約・返信案・日報生成 |
| Gmail / Gmail MCP | メール取得、分類対象の抽出、既読化、返信 |
| Google Calendar | 当日の予定取得 |
| Supabase（PostgreSQL） | メール、Todo、実績、日報、設定、処理履歴の永続化 |
| Tailwind CSS | スタイリングとデザイントークン管理 |
| shadcn/ui | UIコンポーネント |
| lucide-react | アイコン |
| date-fns / @date-fns/tz | UTC・JSTを含む日時処理 |
| Zod | AIの構造化出力と環境変数の検証 |
| Vercel | デプロイ |
| Devin | バックエンドの並列実装、シードデータ、テスト |
 
```text
Next.js ─────────────── Vercel
   │
   ├── Claude API ───── メール分類・要約・返信案・日報生成
   ├── Gmail ────────── メール取得・既読化・返信
   ├── Google Calendar ─ 今日の予定取得
   └── Supabase ─────── データ保存・将来の認証
```
